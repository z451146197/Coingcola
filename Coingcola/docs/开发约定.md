# 开发约定

## 1. 当前优先级
- 先做真实闭环
- 后做结构洁癖
- 冻结兼容层，不在主壳继续做大改名

## 2. 代码改动原则
- 页面尽量少改，优先补服务层
- 兼容服务只做薄适配器，不再塞业务逻辑
- 新能力优先放到系统设置服务、软件管理服务这类真实服务层

## 3. 提交建议
- fix：修复编译或运行问题
- refactor：服务层收口、适配层瘦身
- chore：文案、文档、配置类调整

## 4. 协作建议
- 每轮推送后，提供 commit 或直接说明按最新 master 看
- 明确本轮重点文件与目标
- 默认按 git patch 协作；脚本类改动优先通过 1.ps1 落地
